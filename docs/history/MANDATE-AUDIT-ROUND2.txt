State/ordering conclusions:
- execute records execution ID/lock before its first cross-contract read. Signing state commits only in on_signed; receipt-local panic rollback does not undo an earlier receipt's lock.
- Registration stores derived key before add_public_key; key_registered only changes on successful registration. Wrong derived prefix/read failure can panic, but execution remains unavailable and registration can be retried.
- Gate rejection counts a strike, consumes matching current work and clears lock; read/signer call failure normally clears lock without a strike. Malformed successful signer answer retains timed lock. F07 affects identity after elapsed time; F23 concerns a parse panic before normal failure handling.
- withdrawal takes visible queue before send, now tags retry by sequence and treats zero as refund. It still stores no unresolved-send identity/status: F06. Cancel invalidates older retry sequence after a replacement: F08 fixed. Callback parse/OOG/loss reconciliation remains unverified.

Time/arithmetic/storage:
- Block timestamp nanoseconds are converted to seconds. 24h delay constants are 86,400; exact boundary uses >=. New queue replacements start a fresh delay and cannot accelerate new authorization.
- Proposal TTL=60; build window=300; intent TTL=120; timed entry lock=420. Correct addition/boundary arithmetic does not solve F07's differing callback authority or F19's expired deadline.
- UTC-day turnover bucket is now - now % 86,400; cooldown uses saturating_add. Adjacent UTC days each have their own allowance, consistent with the stated daily policy.
- Input notional rounds up; minimum output/NAV rounds down; wide multiplication and checked NAV sums preserve conservative arithmetic. 6/24-decimal and overflow tests pass. No verified u128 valuation overflow exploit was found.
- Ordinary u64 IDs/timestamp increments are not near overflow at real runtime dates/counts; no attacker-controlled overflow demonstrated.
