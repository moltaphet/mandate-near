# Transaction hash corrections

The testnet driver ([`contracts/vault/examples/testnet_run.rs`](../../contracts/vault/examples/testnet_run.rs))
printed each transaction's hash with `result.transaction().get_hash()`. In near-api 0.8.7 that call does not
return the transaction's hash. The library rebuilds the transaction from the RPC view and puts the real hash in
the rebuilt transaction's `block_hash` field. So `get_hash()` hashes a different object. Every `hash` printed in
the `.log` files of the 7 November and vault2 runs is therefore not the real transaction hash, which is why
explorers and RPC nodes could not find them.

The transactions themselves ran as recorded. The vault state that the logs and readbacks describe is on chain.

**How the real hashes were found.** Every transaction involving the project's accounts was listed from the
public FastNEAR testnet transaction indexer. For each one, the printed value was recomputed exactly as
near-api does: sha256 of the borsh-encoded transaction rebuilt from the RPC view, with `block_hash` set to the
real hash. All 65 printed hashes matched exactly one real transaction, with the same method. The tooling is in
the commit that added this file. The driver now prints `outcome().transaction_hash`, the hash the network
assigned.

The raw `.log` files are kept unchanged as evidence. The READMEs, the main README, the submission notes and
the site now use the real hashes below.
