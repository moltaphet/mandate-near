unique native Intents voucher. It also rejects static historical duplicate

B3. SR-6 COMPLETE WITHDRAWAL AND RECOVERY TRACE

1. Owner+1yocto queues listed positive NEP141 amount to safe receiver with
   now+86400 deadline. Replacement starts a fresh timer. Cancellation advances
   generation. Rearm does not reset a matured request's original deadline.
2. After maturity, permissionless apply requires owner arm, no active guard or
   execution/open signature and >=280TGas. Arm consumed, queue removed,
   never-reused ID allocated, Preparing persisted before any external call.
3. One Intents receipt mints exactly one canonical withdrawal-N source voucher
   through mt_on_transfer, then reads source unit/victim balance. Private first
   callback requires source1 and victim>=amount, then schedules four proofs.
4. Private prepared callback requires current ID+Preparing and exact tuple
   (supply1,source1,sent0,cancelled0), with sufficient recorded victim balance.
   It sets Dispatched before scheduling one marker-FIRST/ft_withdraw-LAST
   Intents receipt. Last action preserves actual terminal U128 return.
5. Full returned amount -> Delivered/guard clear. Explicit0 -> trusted refund,
   generation-matched request requeued unarmed. Error/malformed/oversized/
   positive partial -> unknown/guard retained, no automatic retry.
6. After300s, Preparing can be invalidated before delayed callback dispatch.
   Dispatched recovery requires>=140TGas and races source unit to c.<vault>.
   Cancellation response alone never releases state. Four positive proof reads
   require supply1/source0 and either sent1/cancelled0 or sent0/cancelled1.
7. Sent proof -> DebitObserved, consume old authorization, clear guard. It proves
   initial debit, NOT final receiver delivery or absence of a later refund.
   Those old resolver/refund receipts may overlap later operations. Cancelled
   proof -> safe matching unarmed requeue; owner must rearm, next apply new ID.
8. Failed/null/both-zero/both-positive/inconsistent proof -> guard retained.
   Late old ID/stage callbacks cannot overwrite a new attempt. Named sinks must
   remain uncreated and without implicit/registered/proxy/current/future signing
   authority. Fresh issuer/lifetime issuance premise remains mandatory (F28).

The token_account helper strips nep141: only from an already grammar-validated
mandate asset. Arbitrary outside callers cannot alter the active request or its
token suffix. Receiver=vault or Intents is refused twice. Other real-token
receiver registration/failure semantics still need production evidence.
