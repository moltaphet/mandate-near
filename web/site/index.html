An AI agent that can propose trades, but cannot move the money.

Mandate splits the agent from the authority. The agent runs in a TEE and proposes swaps. A NEAR smart contract holds the only key to the treasury on NEAR Intents, and signs a trade only after checking it against the owner's rules. This page states exactly what is built, what is proven on mainnet, and what is not done yet.

Flow

One trade, six steps

The trade passes two transactions by design: a decision, then an execution. Each step says whether it exists today.

  1. Decision. The agent reads the market and proposes a swap with a minimum output.

    Runs inside an OutLayer TEE, pinned by code hash. Results are returned to the contract by yield and resume.

    planned · M4
  2. Balances and prices. The contract reads the vault's balances on intents.near and a fresh oracle price.

    Stale prices are rejected. Oracle feed format is still to be confirmed.

    planned · M3
  3. Mandate check. Nine gates, in a fixed order. The first closed gate rejects the trade with a named code.

    Exact 256-bit USD math. Each rule has boundary tests and a property test.

    built · tested
  4. Intent bytes. The contract builds the exact raw_ed25519 payload with a V1 expirable nonce.

    Proven: the same bytes built by the vault's code pass mainnet simulate_intents checks.

    built · proven
  5. Signature. The contract asks the MPC network for an Ed25519 signature over those bytes.

    Proven on testnet: the signature is accepted by mainnet intents.near. The vault wiring is not done.

    proven parts · wiring M3
  6. Settlement. A solver publishes the signed intent and settles atomically.

    Not run for a real trade yet.

    planned · M5

Related work

What already exists, and where Mandate differs

Similar pieces exist. We list them here so the difference is stated by us, not discovered by a reviewer. Claims about other projects come from their public docs or secondary reports, and are marked as such.

ProjectWhat it doesWho holds the signing powerWhere the rules run
OutLayer Agent Custodydocs TEE-held wallet for agents, with policies, spending limits and a freeze switch from the owner's dashboard. Keys derived inside a TEE. The agent holds only an API key. Inside the TEE. The contract does not verify each policy decision on-chain.
Shade Agentssecondary source: guide AI agents whose off-chain logic runs in a TEE, with Chain Signatures for cross-chain actions. Chain Signatures, gated by an on-chain agent contract that checks attestations. Off-chain logic in the TEE. The on-chain contract decides which agent may act.
RHEA AI Vaultplanned, not confirmed live: report Planned automated yield across chains, using Shade Agents. Not documented. Not documented.
Mandate (this project) A treasury on NEAR Intents that trades only if the contract's nine gates pass. The vault contract alone. The MPC key is derived for its account, and the agent holds no key. On-chain. Every trade is checked by the contract before MPC is asked to sign. The signed bytes fix amount, deadline and nonce.

The difference is where trust sits. In TEE-based wallets, the policy runs inside the TEE and its result arrives as a signed message, so a reviewer must trust the TEE and the operator. In Mandate, the policy is the contract's code, and the signature exists only after that code accepts the trade. Our claim is narrower than "we have policies". It is that the enforcement point is on-chain and the signing key is unusable without passing it.

We have not tested any competing project. This comparison comes from their public documents.
