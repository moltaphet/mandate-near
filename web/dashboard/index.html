About

A treasury that checks itself before it signs.

Mandate is a policy layer for NEAR agents. An agent can propose a trade. The vault contract holds the only signing key for the treasury on NEAR Intents, and it signs only after nine rules pass, in order, against limits the owner wrote.

The agent cannot withdraw, cannot change the rules, and cannot skip a rule. It has no key. If it is compromised, the worst it can do is propose trades that the contract then rejects.

This page shows the rules, the checks, and the commands that prove them. It does not show live trading, because no live trade exists yet.

FAQ

Questions a reviewer would ask.

Each answer says what exists today. Where something is planned, it says so.

Is this trading live on NEAR?

No. The signature path from the contract to the MPC network was proven on testnet, and the signature was accepted by mainnet intents.near. The vault does not yet read live balances or prices, and it does not yet call the MPC network from its execution path. That is milestone M3.

Can the agent move the money?

No. The agent can only propose a trade with a minimum output and a reason hash. It has no key on the vault account. The vault signs only after all nine rules pass, and the signed bytes fix the amount, deadline and nonce.

What happens if the price feed fails?

Trading stops. A missing or stale price is a rejection, not a guess. The price-freshness lock closes, and the trade is never valued with an old number.

Why this order of locks?

The cheap checks come first: structure, lock and cooldown. Price reads come before the money checks, because the money checks need them. The first closed lock stops the trade, so later locks are not evaluated. The order is fixed, so a rejection always names the same first failure for the same input.

Who can change the rules?

Only the owner. The owner can be an individual account or a DAO account. Tightening a limit takes effect at once. Loosening a limit is planned to take 24 hours, and the owner can cancel it in that window. Pause always works. These delays are planned for version 1, not yet built.

What if the agent is compromised or spams proposals?

It can only propose, and each proposal is checked. Only one proposal can be pending at a time, and none is accepted while a signed intent is still open. The circuit breaker halts proposals after three rejections in a row, and only the owner can resume them. The breaker's counting runs in the execution path, which is part of M3, so it is not active yet.

Where is the proof?

Click any lock to see the test that proves its rule and the command to rerun it. The evidence page lists the mainnet checks and the reproduction steps. Nothing on this page needs a key or funds to rerun.

Does the design promise returns?

No. Mandate limits how much can go wrong and who can change the limits. It makes no claim that any strategy is profitable.

Is the data on this page real?

No. Values in the table, the receipt and the scenarios are sample data, and each one is labelled. Chain-backed values replace them when the contract is wired (M3).
